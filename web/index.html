我们测不了什么

诚实说明局限，比夸大能力更重要

代码可维护性与架构需要人工评审，自动化测不出"写得漂不漂亮"
规格清单外的场景平台只测双方约定清单内的接口与用例，这是双方的责任
性能与容量需另配压测环境。内存数据库测不出真实数据库的性能特征
隐藏后门与恶意逻辑只能辅以静态扫描与人工审计，无法完全自动化
主观质量判断用户体验、文案、设计感 —— 无客观标准，强行量化就退化成 AI 主观判定
◱

技术实现要点

验收环境如何支持依赖数据库的交付物

隔离运行时pg-mem 内存 PostgreSQL + 内存 KV（Redis 常用命令实现）。每个项目一份，互不可见。
进程注入global 变量无法跨进程传递，改用 --require 加载器在子进程内部注入运行时。
种子数据传递父子进程内存不共享，种子数据写成 JSON 快照，由加载器在子进程导入并 await 完成。
协议解耦交付物只连标准协议，不关心背后真假。生产环境把 runtime-bridge 换成真 pg / ioredis 即可。
